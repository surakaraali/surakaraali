## About

<img align="right" src="https://github-readme-stats.vercel.app/api?username=surakaraali&show_icons=true&hide_border=true&hide_title=true&bg_color=0d1117&text_color=c9d1d9&icon_color=a78bfa&ring_color=8b5cf6&count_private=true&rank_icon=github" width="380"/>

I'm a **Computer Engineer** from Istanbul who builds software end to end — from the interface a user touches to the pipeline that runs behind it.

My foundation is **software engineering**: clean architecture, readable code, disciplined Git workflows, and code review as a habit rather than a gate. I've shipped in corporate product teams at **Logo Yazılım** and **FMSS Bilişim**, working inside Agile/Scrum sprints on mobile features spanning performance, accessibility, and authentication.

On the **full-stack** side, I build production web applications with **Next.js, React, and TypeScript** — two of them are live client sites today. On mobile, I work with **React Native** and **Swift / SwiftUI**.

In **AI / ML**, I focus on applied systems: integrating **large language models** into real workflows, designing **recommendation and routing logic**, and orchestrating **Text-to-Speech pipelines** — the core of my graduation project, *Podify*.

I approach every project with a **product engineering mindset**: understand the requirement, find the root cause, ship the smallest thing that solves it well, then iterate.

**Open To**

- Software Engineer / New-Grad Engineering roles
- Full-Stack & Frontend Engineering (Next.js, React, TypeScript)
- Mobile Engineering (React Native, iOS)
- AI Product Engineering & LLM-integrated applications
- Open-source collaboration

## Featured Projects

<details>
<summary><b>Podify</b> — AI-Powered News-to-Podcast Platform · <i>Graduation Project</i></summary>

<br/>

An automated platform that turns the news a user cares about into a personalized podcast — scraping by category, summarizing with language models, and synthesizing speech.

| | |
|:--|:--|
| **Stack** | ![](https://img.shields.io/badge/TypeScript-1e1b4b?style=flat-square&logo=typescript&logoColor=a78bfa) ![](https://img.shields.io/badge/LLMs-1e1b4b?style=flat-square&logo=openai&logoColor=a78bfa) ![](https://img.shields.io/badge/Text--to--Speech-1e1b4b?style=flat-square&logo=audiomack&logoColor=a78bfa) ![](https://img.shields.io/badge/Web%20Scraping-1e1b4b?style=flat-square&logo=googlechrome&logoColor=a78bfa) |
| **Scale** | Multi-category, multi-source news ingestion driven by user selections |
| **Performance** | Fully automated pipeline: scrape → filter → summarize → synthesize |
| **Security** | Model and TTS provider access isolated from the client layer |
| **Impact** | Converts long-form reading into short, on-demand audio briefings |
| **Repository** | [![Repo](https://img.shields.io/badge/PodcastAI-View%20Source-8B5CF6?style=flat-square&logo=github&logoColor=white)](https://github.com/Travel-Assistant-Project/PodcastAI) |

Podify is built as a staged pipeline. A scraping layer collects articles from the categories each user subscribes to; an LLM stage analyzes, filters, and condenses them into structured summaries; and a TTS stage renders those summaries into podcast-ready audio. Each stage has a single responsibility, which keeps the system easy to extend with new sources, models, or voices.

</details>
